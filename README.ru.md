# Porabot

Персональный Telegram-бот для планирования напоминаний и трекинга привычек. Ключевая фича: задача создаётся одной фразой на **русском, английском или испанском** — без мастера, без меню; бот сам понимает время.

## Возможности

### Создание задачи одной фразой

Напишите — бот выделит время и текст задачи:

| Ввод | Результат |
|---|---|
| `вечером принять лекарство` | напоминание в 19:00 сегодня — «принять лекарство» |
| `завтра в 10 утра позвонить маме` | завтра 10:00 — «позвонить маме» |
| `in 15 minutes check the oven` | через 15 минут — «check the oven» |
| `mañana a las 9 tomar vitaminas` | завтра 09:00 — «tomar vitaminas» |
| `каждый день в 9 тренировка` | ежедневное повторение в 09:00 — «тренировка» |

### Напоминания

- **Разовые и повторяющиеся** — ежедневно, еженедельно или любой паттерн через `RRULE`
- **Режим nagging** — повтор каждые 5 минут, ограничен настраиваемым лимитом (по умолчанию 3)
- **Снус** — +15 мин / +1 час / на завтра
- **Тихие часы** — настраиваемое окно, во время которого все уведомления подавляются
- **Восстановление пропущенного** — после рестарта бот присылает сводку пропущенных задач с возможностью «отметить всё» или «снузнуть всё» одной кнопкой

### Привычки

- **Фиксированный режим** — привычка срабатывает в заданное время каждый день; серия считается по метке `due_at`
- **Плавающий режим** — привычка должна быть выполнена в любое время текущего местного дня; серия считается по дате
- **Пресеты** — шаблоны распространённых привычек при создании
- **Серии (стрики)** — `habit_streak_current` / `habit_streak_best` для фиксированных привычек; `fluid_streak_current` / `fluid_streak_best` — для плавающих
- **Undo** — откатывает последнее выполнение и восстанавливает серию до значения, которое она имела до отметки (флаг `habit_undo_pending`)
- **«Не сегодня»** — фиксирует цикл как `not_today` (отдельно от автоматического `missed`); как и пропуск, сбрасывает текущую серию
- **Sweeper привычек** — фоновая задача каждую минуту выявляет пропущенные циклы по состоянию БД, а не по факту отправки уведомления; пропуск фиксируется даже если бот был недоступен, пользователь заблокировал его или nagging отключён
- **Еженедельные и ежемесячные отчёты** — агрегированная статистика выполнения / «не сегодня» / пропуска по каждой привычке, отправляется в настроенный день и время

### Общее

- **Три языка** — полная i18n на русском, английском, испанском (`bot/lexicon/ru.py`, `en.py`, `es.py`); разбор естественного времени работает на всех трёх
- **Таймзоны** — всё хранится в UTC; отображается в местном времени пользователя; DST-переходы обрабатываются корректно
- **Утренний и вечерний бриф** — ежедневная сводка в настраиваемое время
- **Настройки пользователя** — таймзона, язык, тихие часы, лимит nagging, расписание отчётов

## Инженерные решения

1. **Всё в UTC, конвертация при отображении.** `execution_time` хранится как naive UTC в SQLite. Перевод в местное время — только при формировании сообщения. При старте бота `reconcile_jobs_with_db` пересчитывает следующее вхождение RRULE в таймзоне пользователя, поэтому перезапуск в момент перехода на летнее/зимнее время не сдвигает настенное время ежедневного напоминания. Покрыто тестами `test_dst_recurring_reminder.py`, `test_reconcile_dst_next_occurrence.py`.

2. **APScheduler с персистентным хранилищем и регидратацией.** Задания переживают перезапуск через `SQLAlchemyJobStore`. При старте `reconcile_jobs_with_db` проходит все `pending`-напоминания: если задания нет в сторе (пропало после простоя), создаётся catch-up задание на «+1 минута». `last_fired_at` защищает от повторной доставки уже отправленных уведомлений.

3. **Идемпотентный журнал событий привычек.** Таблица `HabitEvent` имеет `UNIQUE(reminder_id, cycle_key)`. `cycle_key` — `due:<unix_ts>` для фиксированных привычек и `day:<YYYY-MM-DD>` для плавающих. `HabitEventDAO.record()` сначала проверяет наличие строки; при гонке двойных нажатий использует `SAVEPOINT` (`begin_nested`), а не `session.rollback()` — откат всей сессии уничтожил бы остальные изменения текущего Unit of Work (счётчики серий, отметку выполнения).

4. **`forbidden_strikes` против вечного долбления.** Каждый `TelegramForbiddenError` (пользователь заблокировал бота) увеличивает счётчик `forbidden_strikes`. При достижении `FORBIDDEN_STRIKES_LIMIT = 3` напоминание исключается из регидратации и nagging прекращается.

5. **Sweeper привычек независим от уведомлений.** `habit_sweeper.py` определяет пропущенные циклы из состояния БД каждую минуту, а не в момент отправки уведомления. Пропуск фиксируется даже если бот был недоступен или пользователь его заблокировал.

6. **DAO-слой и композиционный корень.** Весь доступ к БД — через типизированные DAO (`ReminderDAO`, `UserDAO`, `HabitEventDAO`). `bot/__main__.py` — композиционный корень: сборка инфраструктуры без бизнес-логики.

7. **NLP-парсер в thread pool.** `DatesExtractor` из natasha не реентерабелен; все вызовы сериализованы через `threading.Lock`. Синхронный конвейер разбора запускается через `loop.run_in_executor` — event loop не блокируется.

Тесты написаны в стиле регрессий: каждый тест падал на конкретном баге до фикса, затем применялось исправление. Файлы тестов находятся рядом с исходниками в `bot/services/`.

## Установка и запуск

### Docker Compose (рекомендуется)

```bash
cp .env.example .env
# заполнить BOT_TOKEN и ADMIN_ID
docker compose up -d
```

SQLite-базы сохраняются в `./data/`.

### Локальный запуск

```bash
python3 -m venv .venv && source .venv/bin/activate

# цепочка natasha → yargy → pymorphy2 → docopt не собирается с setuptools ≥ 81
pip install "setuptools<81" wheel
pip install -r requirements.txt

python -m bot
```

Для воспроизводимой установки использовать lock-файл:

```bash
pip install "setuptools<81" wheel
pip install -r requirements.lock
```

### Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | ✅ | Токен Telegram Bot API |
| `ADMIN_ID` | ✅ | Telegram ID владельца |
| `ALLOWED_USERS` | — | JSON-массив разрешённых user ID |
| `TZ` | — | Таймзона по умолчанию (напр. `Europe/Moscow`) |
| `DATABASE_URL` | — | URL SQLite; по умолчанию `sqlite+aiosqlite:///porabot.db` |
| `SCHEDULER_DB_URL` | — | URL APScheduler jobstore; по умолчанию `sqlite:///jobs.sqlite` |

## Известные ограничения

- **O(users) минутные джобы.** Четыре cron-задачи (брифы, восстановление пропущенного, sweeper привычек, отчёты) сканируют всех пользователей каждую минуту. Приемлемо для персонального бота; не масштабируется на тысячи пользователей без дополнительной индексации. Зафиксировано как W4 в `AUDIT.md`.
- **Ввод таймзоны только целыми часами.** Онбординг принимает целочисленные UTC-смещения (напр. `+3`). Получасовые и четвертьчасовые смещения (Индия, Непал, Иран и др.) требуют ручного указания в `.env`. W8 в `AUDIT.md`.
- **Whitelist реализован, но выключен по умолчанию.** `WhitelistMiddleware` находится в `bot/middlewares/whitelist.py`. Включить в `bot/__main__.py` перед публичным развёртыванием.
