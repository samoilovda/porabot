Дата: 18 октября 2026. Основание: [инструкция агенту](2026-10-18-ui-ux-agent-instructions.md) и [аудит](../audits/2026-10-18-ui-ux-audit.md). Исходная версия приложения — `23fe24f`; аудит и инструкция сохранены в `4b66963`.

Основной объём A–D реализован. Локальные проверки пройдены; приёмка в настоящих Telegram-клиентах остаётся перед релизом. Этапы E/F, персональные шаблоны и голосовой ввод в эту реализацию не входят.

## Данные и совместимость

- При `init_db` добавляется таблица `ui_contexts`: короткий токен, владелец, тип, JSON-снимок, срок действия и результат. Изменений существующих столбцов для этой функции нет. Повторная инициализация безопасна; отдельная проверка моделирует предыдущую схему без новой таблицы и сохраняет задачу, время, региональный пояс и старую настройку повторов.
- Навигационные контексты по умолчанию живут 24 часа. Снимок отмены отметки — два дня; доступность действия дополнительно ограничена актуальным циклом. Маркер уже предложенных уведомлений хранит пустой payload со сроком десять лет. Истёкшие записи удаляются при создании контекста и часовым обслуживанием FSM; сброс пользователя удаляет его контексты.
- Новые callback содержат короткие идентификаторы; запросы, длинные Unicode-теги и массивы ID остаются на сервере. Контекст проверяется по владельцу и сроку. Старые callback продолжают распознаваться.
- Отметки привычек используют блокировку записи SQLite и уникальность события цикла. Массовая операция фиксирует изменения и результат в одной транзакции. Проверены повтор, конкурирующие отметки и отказ commit.
- FSM остаётся SQL-backed. Middleware освобождает блокировку после обновления пользователя перед отдельной записью FSM; обработка пользовательских переходов сериализована через `SimpleEventIsolation`.
- Существующие IANA-пояса не конвертируются автоматически. Новые фиксированные дробные зоны сохраняются как `UTC±HH:MM`; целые сдвиги совместимы с `Etc/GMT`. Внутренние даты остаются UTC. ICS содержит определение фиксированного пояса и корректно заключённый в кавычки TZID.
- Старые API-поля Mini App и проверка подписанного Telegram initData сохранены. Поля количества исходов добавлены без изменения формулы устойчивости. Новых write-endpoint Mini App нет.
- Текст задач убран из отладочных сообщений парсера; SQLAlchemy скрывает параметры запросов в исключениях. Новая продуктовая аналитика не добавлялась.

Новые Python-регрессии находятся в `tests/services/test_ui_ux_regressions.py` и `test_ui_experience.py`. Они проверяют данные в настоящей локальной SQLite: перезапуск с новым сеансом, владельца и TTL, доступ к поздним страницам, переименование, снимки batch, повтор/конкуренцию, отмену отметок и историю, timezone preview, фиксированный сдвиг зимой/летом, ICS, уведомления и сброс. Существующие проверки миграций, scheduler, экспорта и API остаются в полном наборе.

Telegram-обработчики проверены с подставными сообщениями и планировщиком; тесты API используют локальный HTTP и тестовую авторизацию. Браузер запускается настоящий, но SDK и ответы API синтетические. Проверены испанский профиль, 320 px, крупный текст, клавиатура, тёмная тема, частичный 500, 401, 429, таймаут и повтор без потери готового блока. Это разные уровни проверки; успешный браузерный тест не означает приёмку в Telegram.

Для frontend-проверок нужны Node 22+ и установленный Chromium/Chrome; нестандартный путь задаётся `CHROMIUM_PATH`. Dev-зависимости закреплены в `package-lock.json`, приложение остаётся без сборки. В CI добавлены `npm ci` и `npm test`; удалённый запуск CI в рамках локальной проверки не подтверждён.

## Перед релизом и следующие этапы

Настоящие Telegram iOS/Android/Desktop, доставка уведомлений, экранный диктор и взаимодействие с реальными мобильными safe-area не проверены. Перед публикацией пройти семь ручных сценариев из инструкции в тестовом боте, включая смену пояса, паузу, удаление/восстановление и смену расписания. Production-развёртывание и отправка реальных Telegram-сообщений не выполнялись.

E — недельные цели, F — входящие без даты, исследовательские F5/F6 остаются отдельными задачами согласно исходной инструкции. Для них не создавались фиктивные данные или неработающие кнопки.
